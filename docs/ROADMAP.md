# 后续工程路线图

## 已完成与当前节点

P3 系列已收尾。QQ 单平台于 2026-11-17 完成实机验收，P4 QQ + 飞书双平台于 2026-11-18 完成实机验收。P4 合并提交为 `825d064`。当前 `main` 是唯一实现基线，已验收的双平台核心仅在新阶段发现通用缺陷时作必要修改。

历史 P1–P6 编号仅用于引用当时材料。双平台验收后的新路线固定使用 `FFA-N01` 至 `FFA-N08`。任务提示、分支、计划和验收记录统一引用正式编号与名称。编号保留原义。如有子阶段，先在本路线登记从属关系、范围与准出条件。

## 固定实施顺序

| 编号 | 阶段 | 目标与依赖 |
| --- | --- | --- |
| FFA-N01 | 记忆系统改造 | 基于当前 Memory 与 Principal。完成跨平台经历和人物连续性设计及验收，为 FFA-N02 提供活动与记忆基础。 |
| FFA-N02 | Bilibili 接入 | 依赖 FFA-N01，复用成熟插件，形成 QQ、飞书、Bilibili 三平台联合运行。 |
| FFA-N03 | 命令框综合管理器 | 在前三平台边界稳定后建立统一的命令框入口和管理接口，供 Work 与后续可视化界面复用。 |
| FFA-N04 | Windows 本地 Work | 依赖 FFA-N03，建立本地执行、权限和任务协议。 |
| FFA-N05 | 远端 Linux Worker 接入 | 依赖 FFA-N04 的任务协议，验证 Chat/Core 与远端 Worker 协作。 |

| FFA-N08 | 长期维护 | 在前述阶段后持续开展，无固定结束时间。 |

### FFA-N01 · 记忆系统改造

状态为验收中。独立候选分支已实现事件证据检索和恢复路径，正式发布仍需通过独立中文盲评、低配持续并发与 QQ、飞书实机验收。见[认知检索实验报告](research/FFA_COGNITIVE_RETRIEVAL_REPORT.md)。

从[当前记忆实现](developer/MEMORY_ARCHITECTURE.md)与[记忆分析和迁移](developer/MEMORY_ANALYSIS.md)进入。先核查现有 Activity、Fact、记忆卡、Principal 和 SurfCore 派生机制，再确定数据模型、升级迁移及验收。建立 Bot 自身跨平台、跨场景的经历记忆。Principal 对应的人物互动画像涵盖熟悉度、好感度和互动风格，使同一人在 QQ、飞书和后续平台保持连续性。

保留私聊、群聊等情境隔离。跨场景的人物画像应按规则生成可用摘要，逐条人工授权私聊内容进入群聊仅作为可选操作。明确来源、证据、可信度、记忆衰减与卡片管理。验证删除、撤回和权限变化能清理或阻断所有受影响派生数据，再进入 Bilibili 集成。

### FFA-N02 · Bilibili 接入

适配层负责 Bilibili 原生认证、对象标识、API 与回执转换。通用 Core 管理 Principal、Persona、Permission、Memory、活动来源与审计。独立 Agent 或插件负责浏览、读取、内容选择和已授权的操作。优先评估成熟插件，按实际能力选择接入方式。

在明确授予范围和额度后，可主动读取公开内容并记录已观看视频、已读取内容、确认完成的操作及形成的兴趣。账号授权、私有数据访问和任何外部写入需明确许可。评论、发布、关注等对外行为按计划设定逐次确认及回执核验。状态未知的操作须核实结果后才能重试。最终验收三平台共用 Core 的运行与权限边界。

### FFA-N03 · 命令框综合管理器

用简单命令框提供平台与 Provider 状态、Persona、Memory、Permission、Task、Plugin 和基础配置的查看与管理。建立统一命令、权限检查和返回结果约定。可视化界面安排在 FFA-N06。

### FFA-N04 · Windows 本地 Work

确定性任务直接执行，复杂任务交给 Agent。DSH 是复杂任务执行引擎。规划本地任务执行、文件与进程操作、截图、日志获取、状态查询、取消、结果回传、长任务和权限控制。验收任务在完成、取消、失败后均有可查询的结果。

### FFA-N05 · 远端 Linux Worker 接入

Chat/Core 负责身份、授权和任务协调，Worker 在获准范围内执行。设计 Task Router、任务提交、状态同步、日志回传、文件传输、取消、在线状态、故障恢复与安全认证。Windows 本地 Work 和 Linux Worker 尽量遵循统一任务协议，明确能力协商与重连后的状态核对。

### FFA-N06 · 可视化综合管理器

复用已稳定的管理和任务接口，提供平台及 Bot 状态、Memory、Persona、Permission、Task、Local Work、Remote Worker、Plugin、日志、配置、健康检查及更新、迁移、恢复入口。

### FFA-N07 · 插件兼容层与其他社交平台

建立正式 Plugin Compatibility Layer，统一接入 Persona、Memory、Principal、Permission、Task、Notification、Activity 和 Provider/Agent 生命周期。逐步接入小红书、抖音、微博及后续平台。优先复用成熟插件。第三方能力必须经 Core 校验身份、权限、记忆范围和主动行为。

### FFA-N08 · 长期维护

持续处理缺陷、性能与稳定性、固定依赖升级、上游兼容、安全修复、平台 API 变化、迁移工具、用户反馈、文档与小规模增强。较大的架构变更须另立目标与验收标准。
