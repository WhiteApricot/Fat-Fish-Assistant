# 开发参考

平台适配层把可信原生事件转换为 `MessageEvent`，其中包含独立的 Provider、发送人、会话和消息标识。Registry 从 schema 2 配置生成 Provider，Runtime 校验来源、授权和去重，Gateway 调用共用的命令、记忆和提醒服务。飞书已接入，OneBot 适配接口供后续 QQ 接入使用。适配器分别承担原生路由、引用读取和发信。[通信配置示例](../examples/config/ffa-communication.json)

AstrBot 持有原生平台连接。FFA 的启动入口在同一事件循环中加载宿主，以便飞书 SDK 的收包任务随宿主运行。更换依赖时校验 [固定来源](../manifests/sources.json) 和现有补丁。飞书字段与 SDK 行为在适配层处理，消息准入与身份策略在通用层处理。

身份目录通过统一身份关联多个平台账号。新人工绑定在另一平台的私聊中兑换邀请码。会话授权以平台实例和会话标识为边界。主动投递与即时回复均在发信前重新核对授权。引用只接受适配器验证的同会话消息，历史中的用户内容作为模型资料。

内部主 Agent 处理日常对话及按需工具调用。`/naturalcommand` 控制管理工具，`/websearch` 控制公开搜索。管理工具由 Gateway 绑定到原始事件，在命令注册中心验证参数并调用同一处理器，执行前再核对权限。高危操作依旧由确认流程完成。一个消息轮次可提交一项管理操作，并可提前只读查找目标。显式命令在 Gateway 直接进入注册中心。带自然语言参数的显式提醒命令只提供其绑定的提醒操作。

联网搜索继续执行 DeepSeek 搜索请求、Draft、Review、证据验证及需要时的补充查询。出现超时时发送应用当前人格的状态提示，仍有证据可处理时说明继续核对。搜索和转发资料均作为数据处理。需要组合两个能力时，先执行来源明确且独立于搜索结果的管理操作。

Gateway 在首条普通文字通过准入后立即启动处理。同会话、同发言者的后续文字通过准入后更新轮次版本和原生接收时间，取消尚未提交的旧处理。最终发送和管理写操作在事件循环内取得提交资格，等待中的输入获准后会重新生成。超过单轮合并上限的输入进入下一轮。正式模型计算和剩余回复节奏可重叠。平台诊断区分服务器创建、原生入口、授权、预处理、Agent、工具、每次 IM API 请求及最终回执。受支持的 Agent 回传可记录 Token。客户端展示需要客户端来源的观测。

从项目根目录设置 `PYTHONPATH=src` 后运行 `python -m unittest discover -s tests`。飞书原生契约测试需要锁定的 AstrBot 环境。真实模型、账号、WebSocket 及投递使用独立验收实例验证。依赖构建和软件升级见[运维说明](OPERATIONS.md)。

Provider 定义可用 `platform_capabilities` 为指定平台追加能力，运行时以实例清单校验。飞书主动发送支持本地图片与独立文件，经 AstrBot 原生组件和上传方法处理。图片可与文本及群提及合并成一条富文本消息。通过 `Outgoing.media` 传给 Provider 的本地路径应由可信调用方选定。文件上传失败或格式不支持时，Provider 在提交 IM 消息前返回失败。
