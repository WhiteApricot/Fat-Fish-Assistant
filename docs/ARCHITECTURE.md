# 当前工程架构

采用“自有集成框架 + 外部依赖动态获取 + 独立运行实例 + 标准化管理接口”。保留 AstrBot 唯一消息出口和既有权限、记忆、人格、群聊与多模态逻辑。本轮只治理工程，不新增聊天能力。

|目录|内容|边界|
|---|---|---|
|src/p2c、src/p2d|既有自有权限和聊天适配|保留已验收行为与数据标识|
|src/fat_fish_guard|正式安全适配模块|只有这一份安装为插件|
|src/feiyu_guard|旧 Python 导入薄别名|不是第二份插件或消息处理器|
|patches|必要核心/插件的行级修改及哈希|没有完整上游文件覆盖副本|
|manifests|来源、提交、URL、哈希、许可、兼容条件|没有依赖载荷|
|scripts、ffa.py|下载、组装、维护和管理契约|不实现 GUI、聊天或 Work 调度|
|tests|合成和契约测试|真实 QQ、VM 与迁移单独验收|

安装根与仓库分开，包含受限的 installation.json、cache、envs、releases、instance、logs。release 保存动态取得的上游原文、实际应用的补丁及 payload-manifest；运行前校验文件和插件，失败停止。实例的 private/data/persona 与代码分开。代码升级只切换已校验发布和插件，不倒灌旧数据库。

必要核心补丁仍覆盖早期权限入口、上下文、调度、工具和发送。现有上游 Hook 无法证明安全等价时保留补丁；不以零补丁作为目标。插件的判断子集从固定源运行时取得，调用者仍负责鉴权、epoch、速率和唯一发送出口。

当前机器已安装组件和运行实例保持原状。新候选的组装与启动只在隔离空白测试实例验证；不自动把旧正式实例切换到新名称或新接口。旧运行入口保留兼容所需材料，其余历史归入本地 Backup。

未来 P6 可直接调用管理 JSON 契约；当前没有 HTTP 管理监听器。Dagu/Work 只有 reserved=true、installed=false 的描述项，不启动原型；云拓扑仍属后续设计，不提供伪实现。
