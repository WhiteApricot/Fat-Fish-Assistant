# 后续阶段长期工程规范

以下是尚未实施的长期设计要求。阶段状态见 [路线图](ROADMAP.md)。具体第三方版本、API、部署发行版和资源数据须在对应阶段重新核验。

## 消息主体与执行主体

AstrBot 保持唯一聊天与人格主体。未来 Controller、调度器、代码/训练工具及 Worker 只回传事实、进度、文件和结果，不产生第二套对外人格或绕过消息出口。平台群管理员、Bot 群管理员和全局主人是不同授权域；Work 只向明确授权的主人级能力开放，群管理员不因管理群而获得主机权限。

执行请求保留用户原始提示、会话关联、任务 ID、项目根、授权者、目标 Worker、超时与取消策略，不擅改目标。消息侧申请、确认、排队和真正执行均复验当前权限。撤权和黑名单生效后，不允许排队任务或后台输出继续越权发送。

## P3 Linux 最小适配与云原型

从 Linux 环境检测、用户目录/权限、运行库、锁定下载与版本校验开始；按平台分离服务管理与路径策略，复用现有 JSON 管理契约。原型阶段只实现必要组件，不要求将所有 Windows 模型、QQ 客户端和插件完整移植。

原型验证 Linux 调度侧与本地受控执行侧的最小任务、状态和文件传递。Dagu 的适用版本、角色、通信机制与认证方式在 P3 通过实际源码和最小演练确定，不将候选名词当作当前已验证能力。不得因原型实验擅自把现有 QQ 消费者迁到云端或同时运行两套消费者。

以 2C4G 为目标上限，测量整机常驻与峰值内存、CPU、磁盘、队列和并发；先部署最小原型再评估额外模型。达不到预算时采用减并发、减少原型组件或保留本地计算，记录结果，不能未经测试宣称完整栈适配。

通信采用认证、最小暴露面和明确的凭据轮换/失效机制；选定加密传输与远程管理方式后实际验证拒绝未授权请求。公网开放、云费用与重大权限变化按对应阶段授权办理，本轮没有建立公网服务。

覆盖短时/长时断线、Worker/调度侧重启、超时、重复提交、凭据失效及恢复。成功的 echo、端口连接或 ping 不能代替任务、文件哈希与状态一致性测试。

## P4 本地 Work

先完成本地受控文件、代码和训练能力。授权目录使用解析后的真实路径，检查符号链接/重解析点，拒绝穿越；同一项目使用任务锁，明确并发限制和运行账号。消息内容、工具返回或仓库文本都不能自行提升操作权限。

会话继续须有可追溯的会话标识和原始请求，不将日志拼接冒充工具原生会话恢复。任务状态和真实 OS 进程状态分别持有，使用进程身份校验和持久化记录；调度连接丢失不能被直接解释为训练已经停止。

定义待执行、执行中、取消请求、成功、失败、状态未知等状态及转换；取消须核对真实进程和子进程。断线重试不得重复启动同一训练任务，幂等与恢复通过实际故障演练验证。训练 checkpoint、参数、依赖、日志和结果分别追踪。

原文件按授权范围传输，记录大小/哈希/用途；需要原始文件时不以截图、压缩图片或文字摘要替代。大文件、敏感目录和有破坏性的操作沿用明确授权边界，不能由后台自动扩大。

## P5 生产级 Linux 与协同

在 P3 原型和 P4 本地能力基础上完成生产 Linux 发行版适配、服务用户、持久化目录、自动恢复、监控、容量和安全治理。Chat/Controller/Worker 的最终分布以实际资源和安全测试决定，不把 2C4G 当作所有组件必能常驻的保证。

维护单一生产 QQ 消费者；跨机迁移先停写，按原生数据库与索引机制备份/恢复，再切换。多个数据库不宣称未经验证的原子一致性，旧快照不能覆盖新聊天。保留版本兼容、失败回退、凭据轮换和离线恢复流程。

覆盖长期运行、压力与背压、消息重放/去重、跨机失联、持久任务恢复和安全拒绝。生产云、真实账号登录和发布不由前期原型自动授权。

## P6 PC 集成管理

桌面工具调用已形成的管理接口管理账号、实例、服务器、依赖、插件、服务、备份与版本。保持业务权限和底层组件控制的唯一实现，不在 GUI 再做一套鉴权、PID 管理或数据恢复逻辑。

远端管理接口按 Linux 适配扩展；当前 Windows CLI 的 schema/错误码是基础，不代表当前已经提供远程管理 HTTP 服务。凭据留在受控本机/服务器，日志导出脱敏；二维码与必须人工确认的登录交给用户，UI 不能隐式扩大权限。

## 插件准入

独立插件具备独立配置、存储版本、安装依赖、启停/卸载和后台任务清理契约。平台可访问消息不等于调用者获准读取任意会话；定时恢复不等于旧授权仍有效。重任务需考虑隔离、超时与资源上限，不能依赖同进程异常捕获保证所有崩溃不影响核心。
