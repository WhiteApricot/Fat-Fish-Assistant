# FFA Cognitive Retrieval 实施计划

1. 审计基线，记录原始 35 题哈希及三种 BGE 表示。保护旧工作树，独立分支仅包含检索所依赖的新库模块。无部署。
2. 构造 30 个隔离的中文故事组，各含 5 个问题，混合近义、时间、动作/状态、歧义、未授权和去除证据。以基础故事为分割单位，先锁定开发、验证及冻结分组。检查每题可追溯的 Gold、允许候选、难负例及判定标准。机器检查与内部校阅分开报告，独立人工复核为未完成状态。
3. 使用旧固定 0.60 为 A，B 加 SQLite posting 上的 BM25/RRF；C 引入确定性 QueryIntent 和可信完成/主体；D 加事件、发生时间、对象匹配；E 加证据强度、澄清与拒答。保留同一授权底层，禁止因为实验去掉 ACL。RRF 以 60 为常量，只融合顺位。结构信号的匹配/冲突独立诊断，不把余弦与 BM25 原生分数直接混加。不访问实时聊天记录。
4. 只在同一数据、模型和设备条件下比较 A–E。一次生成/保存模型向量，让对照公平。冻结样本不参与参数选择。分别统计候选 Recall@1/3/5/10、MRR/nDCG/Precision 和最终决策、证据、拒答、澄清、硬约束。消融拆开主体/状态、时间、BM25、RRF、事件重排、证据判断。Windows 实测与 Linux 限制环境、普通聊天 P95≤150ms 和真实端到端 4～6.5 秒分开证明。
5. 涉及 `event_query.py`、`repository.py`、`retrieval.py` 与离线评测、回归和研究文档。QueryIntent 字段可空；从受信 source/event 提示已明确主体、成功状态和 UTC 时间。未识别、模型不可用时保留词法/结构化或拒答。实际库存仍未切换，无新依赖。
6. 自审与停止条件：不得因低余弦泄露跨域、复活擦掉的证据，或将计划说成完成。保持旧回退路径与冻结验收门槛。未完成人工复核、真实低配或冻结集门槛时不宣布 N01 签收。最后一次本地提交，无推送。

## 实验入口和判定顺序

1. 以可信准入生成的 `Audience` 和请求时刻为输入。`EventIntent` 的主体、动作、状态、时段可缺省，解析器不能增加 scope。将来源的 `occurred_at` 和 `known_at` 分开，未来发生或当时尚未知晓的事件均不进入候选。
2. 读取最多 48 条有证据的有效事件。同一当前修订可以连接多个支持来源。候选按 `(item_id, rev, event_id, source_id)` 追踪。词法以问题前 300 字的最多 12 个 term 生成 BM25 候选，向量以既有模型空间生成有界的独立候选。
3. 通道融合得分为各通道 `1 / (60 + rank)` 之和。D/E 首先比较结构冲突数，再比较时段、动作、状态和对象的命中数。明确近期意图时比较事件发生时间，然后比较融合得分。同一条目只取最匹配的问题证据，最多保留前十个解释。
4. E 要求支持来源可信且作用域有效。用对象锚点和结构匹配判定资格。确认型问题要求对象支持。其他问题可借助时间、动作与状态，或至少同时具有词法候选和 0.60 的语义分。多指代时可请求澄清，缺可信支持返回拒答。
5. 向量超时后仍可评估有授权的确定性候选。SQLite 初查、向量和末次复查各有限时。发布候选前以同一身份复查原始修订和证据元组。复查失败时拒答且清空候选。该入口不进入普通聊天快路径。

自审发现两个基线限制。A 的候选指标应在 0.60 阈值前计算，回复指标在阈值后计算。旧 35 题的公开检索脚本预先过滤部分反例，因此补充写库后撤回、平台群隔离、他人私聊和已取消事件的测试。所有评估用合成 SQLite，避免授权和真实数据进入夹具。
