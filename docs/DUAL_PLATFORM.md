# 双平台运行

QQ 与飞书使用同一 AstrBot 宿主、PlatformGateway、CommunicationRuntime、身份目录和记忆服务。通信配置使用 schema 2，providers 中分别登记 qq 和 lark，并保持实例 ID 唯一。原生凭据仍由 AstrBot 对应平台配置持有。

## 共享与作用域

个人身份以 Principal UUID 为主键。已验证的跨平台绑定共享个人记忆、偏好和全局角色。会话键包含平台、Provider 实例、机器人、会话类型、会话标识和线程。消息去重、引用、撤回、群记忆、群人格、回复任务和提醒目标均沿用完整会话键。

飞书同组织用户的认证消息携带应用、安装组织、发送者组织、发送者类型和 open_id。原生适配层仅在应用匹配、两个非空组织标识一致、发送者为用户且账号与当前消息一致时接纳为普通成员。该流程创建独立 Principal，保留封禁与已解绑账号状态。跨平台个人身份合并继续通过 /invite 和 /link 完成。普通成员身份持久化，群准入和群管理员资格仍按原群范围校验。组织成员首次准入不会赋予全局管理员身份。

## 启动与恢复

受管启动入口在创建平台监听任务前，在同一 asyncio 循环中预加载启用的飞书 SDK。SDK 冷导入可能较慢，预加载避免后续同步导入阻塞已经启动的 OneBot ASGI lifespan。启动时保留固定依赖版本。

Runtime 为每个 Provider 单独维护启动锁、启用状态、错误类型、启动次数和健康检查时间。health_snapshot 返回这些字段，restart_attempts 统计 FFA 接入包装层的重新启动尝试。原生 WebSocket 心跳和重连次数由宿主持有，健康检查时间以检查结果为准。

FFA disable/enable 控制对应 Provider 的业务接入闸门和钩子。AstrBot 管理原生连接生命周期。宿主退出会停止两个平台，恢复单个平台的原生连接应通过 AstrBot 对应适配器管理入口或该平台自身重连机制执行。

## 提醒与主动投递

提醒持久化完整会话键、创建者账号及 Principal、目标账号及 Principal。投递前先检查对应 Provider 就绪状态，再查询当前权限并预留发送账本。QQ 需要同一机器人同时具有 API 与事件反向 WebSocket 客户端。离线期间提醒保持待执行，另一 Provider 可以继续投递。

发送前仍再次检查授权。已成功发送的操作由目标作用域及操作 ID 去重。发送结果未知时保留账本并等待可信回执核对。跨平台同时到期的提醒使用不同目标作用域。

## 人格与新实例

人格目录中的 Persona_Master.md 需要通过受管实例初始化流程写入 AstrBot 原生人格数据库，并将默认人格设为 feiyu-v1。只复制人格文件不能完成数据库初始化。诊断时应同时核对文件、数据库 system_prompt 和 PersonaManager 对两个平台会话的实际选择。

## 验证边界

自动化可以模拟外部事件、断连和回执，并运行真实 FFA 核心及固定 AstrBot 适配器。真实平台的授权、连接和客户端接收结果应单独登记。长时间运行稳定性需要持续运行证据。
