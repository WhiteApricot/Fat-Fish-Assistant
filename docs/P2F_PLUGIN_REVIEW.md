# P2F 系统级需求与架构审查

> 本文保留P2E阶段的审查时点。2026-11-03 P2F已实现自有转发/提醒插件及权限适配；当前接入、限制和验收结果分别见 [使用与架构](P2F_USAGE_AND_ARCHITECTURE.md)、[权限设计](P2F_PERMISSION_DESIGN.md) 和 [内部报告](P2F_INTERNAL_TEST_REPORT.md)。下文“尚未实现”描述历史状态，不作为本轮完成声明。

本轮仅审查，不实现聊天记录读取或提醒业务，不询问业务细节。检查对象是 sources.json 固定提交的实际源码，结论不依赖最新线上文档。

## 系统级要求

两个功能各自为独立插件，独立安装/配置/数据/依赖、启用/停用/卸载；不得修改 AstrBot 或 NapCat 核心。卸载策略明确区分停用、保留数据和清除数据；任务取消和异常处理不能影响核心聊天。所有入口遵循实例主人、白名单、黑名单、群作用域、撤权 epoch、速率与唯一发送边界。

聊天记录插件仅读取平台当前账号实际可见且调用者有权访问的消息；消息 ID 不构成权限凭证。合并转发解析必须限制深度、节点数、体积与超时，不枚举陌生会话或扫描私人数据库。平台未提供的历史不能由 get_msg 推导为可遍历完整群历史。

定时插件独立持久化任务与授权上下文，使用明确时区，定义错过触发、重启恢复、并发、幂等和有界重试。触发和真正发送前都复验当前权限；停用/卸载取消后台任务，撤权任务不能继续发送。到 P2F 再确定业务级规则。

## 实际已有能力及限制

|能力|实际源码证据|判断|
|---|---|---|
|注册、加载、重载及原生 terminate|astrbot/core/star/star_manager.py；现有隔离原生退出日志|有基础；具体插件卸载、后台任务清理仍需各插件验收|
|事件、配置、主动发送|star/context.py:get_config、send_message；platform/sources/aiocqhttp|有原生接口；后台直接 send_message 并不自动继承完整自有事件权限上下文|
|读取单条消息、引用与合并转发|aiocqhttp_platform_adapter.py 的 get_msg 与现有引用适配；OneBot call_action 通道|单条引用接口有源码依据；get_forward_msg/历史 API 的实际可用性需 NapCat 实测，不能声称可读取任意历史|
|配置和私有存储|原生配置、实例 data/plugin_data、插件数据目录|支持独立命名空间；需数据版本、备份范围、导出/卸载协议|
|持久化调度与重启恢复|core/cron/manager.py 的 AsyncIOScheduler、sync_from_db、persistent；CronTrigger/DateTrigger|存在基础；basic handler 重注册、时区、错过触发及重试语义尚须插件实测|
|安全边界|自有 scoped_gateway、epoch、黑名单和现有发送回归|现有聊天边界保留；后台任务必须引入显式授权上下文，不能直接复用无上下文的底层主动发送|
|异常隔离|原生插件加载和回调异常处理|属于同进程隔离，不能保证阻塞调用或进程崩溃不影响 Bot；禁止后台无限重试/同步长阻塞|
|独立管理|上游插件管理器；当前框架版本化整体插件升级/回滚|现框架 CLI 不承诺任意插件热卸载；未来须受控暴露原生能力及配置/存储管理契约|

## 缺失项与准入

P2F 具备以原生独立插件开展开发的基础，尚不具备“任何后台任务可安全直接发送”的无条件准入。首个业务实现前须在自有层完成公共插件契约：显式目标作用域/授权者/epoch、发送前复验、受控依赖安装、持久任务恢复协议、停用取消与数据生命周期。优先使用现有 Hook 与自有适配，不预设需修改上游核心；若确实缺乏安全等价扩展点，先报告，不绕过网关。

本轮新增的是需求、证据与准入契约文档；没有新增插件、调度器或消息发送入口。不得把文档契约描述为已实现接口。P2E 人工群聊、完整服务和现有回归通过后，由维护者另行确认启动 P2F；P3 Linux 同样只具备规划与管理契约基础，尚未实现。
