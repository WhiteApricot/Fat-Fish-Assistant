# 消息事件与 Communication Provider 契约

## 当前 Windows 适配

SnowLuma 通过鉴权的回环反向 WebSocket 连接 AstrBot 的 aiocqhttp 适配器。FFA 配置本机监听与预期机器人身份。SnowLuma 客户端配置在官方 WebUI 中完成。网关读取 AstrBot 事件的发送者、群号、会话标识和结构化消息组件。文本用于指令或聊天，At 用于识别真实提及，Reply 和 Forward 分别用于引用与合并转发的恢复。

管理权限从事件身份和受信任的群成员资料确定。转发内容、模型输出和网页属于输入资料。健康插件使用 get_status/get_login_info 提供只读连接证据。消息入口和最终发送检查见 [网关](../../src/fat_fish/gateway/gateway.py)。

## P3-A 契约草案

适配器把原生输入转换为统一事件，再调用 Core。统一事件包含事件 ID、版本、Provider 实例、平台、机器人账号、发送者账号、会话 ID 和类型、时间、结构化消息、引用与能力信息。平台 ID 在平台与账号命名空间内解析。原生字段留在适配边界，转发内容不得充当认证身份。

Provider 声明生命周期、独立配置、健康快照及消息能力。发送请求携带目标账号与会话、结构化消息、关联 ID 和幂等键。路由在投递前校验权限和能力，并返回结果或明确的不可用原因。跨平台账号绑定需授权且可撤销。身份解析、去重及权限判断先复用既有逻辑，避免影响历史会话数据。

首轮以一个 Windows QQ 入站与回复链路建立契约，使用相同夹具对照旧行为，再模拟独立第二平台的身份、会话、连接故障与能力差异。
