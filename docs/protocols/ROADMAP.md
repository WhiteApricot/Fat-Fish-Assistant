# Fat-Fish-Assistant（肥鱼助手）工程路线图

当前 Windows 交付基于 `backup/snowluma`。P2 实现受控聊天、会话管理、安装及加密迁移。SnowLuma S1 完成特定范围实机原型验证，后续基线加入独立官方运行时管理。参见[现行功能](../FEATURES.md)和[S1 历史验收](../history/S1_WINDOWS_SNOWLUMA.md)。下列阶段均为待开发，B 站接入按实验性能力验证。

## P3 · 多平台聊天与记忆

| 阶段 | 交付及验收 |
| --- | --- |
| P3-A 多平台通信与核心解耦 | 定义统一平台事件、身份、权限、消息和 Provider 接口。逐步移除 Core 的 QQ/OneBot 硬编码。保留现有指令、权限、人格、记忆、去重和迁移行为。以现有 QQ 夹具和模拟第二平台验证。 |
| P3-B 统一记忆与最小插件治理 | 实现 Memory Service、完整行为事件、来源和权限，验证 LivingMemory 旧数据迁移及隔离。研究 SurfCore，优先评估组件复用或窄接口适配，避免导入冲突的宿主。模拟外部 Agent 的成功、失败、重试、乱序、授权撤销和跨域拒绝。验证最小插件登记、启停、依赖、风险、健康和幂等。 |
| P3-C 飞书、QQ 与 B 站联合验证 | 接入主要通信平台飞书，实测飞书和 Windows QQ 同时运行、连接故障相互隔离、授权账号绑定、会话续接、记忆授权和人格一致性。可选接入 `dsh-bili-whale` 测试 B 站浏览、日记、互动和行为追踪。 |
| P3-D 安装器与组件管理 | 默认提供飞书适配及依赖安装。完善多平台组件安装、配置、启停、诊断和健康检查。SnowLuma 仅接受用户指定的本地原始包或有效安装目录，移除基线自动获取路径及内置镜像、下载命令，保留本地校验、官方登录及回退能力。 |
| P3-E Linux 部署与兼容验证 | 支持 Ubuntu 24.04、WSL2 和云服务器。验证干净安装与迁移、Core、记忆、飞书聊天、权限保护、服务重启和备份恢复。盘点 Windows 特有路径、锁、进程、凭据和二进制，预留通信与社交插件扩展。在稳定 QQ 组件选定前暂停 QQ 组件 Linux 移植，SnowLuma Linux 适配不属于交付。 |

国内社交扩展优先覆盖 B 站，再评估抖音、小红书。Telegram 暂无优先开发计划。P3 的 DSH 插件实验允许使用最小测试运行时或桥接，完整 DSH 集成在 P6 交付。

## P4–P9 · Work 与 Agent 扩展

| 阶段 | 方向与验收 |
| --- | --- |
| P4 Windows Work | 独立 Work Controller、任务 ID 和状态、Windows Device Service，覆盖脚本与训练、进程、文件、截图、日志、结果和取消恢复。验证权限、幂等和重启对账。 |
| P5 远端通信 | Work 与远端 AstrBot 建立认证通信，支持跨平台任务通知及续接、进度与文件回传。验证断线、重复乱序、凭据撤销和结果权限。 |
| P6 DSH 集成 | 接入 DSH 运行时和受控设备工具，复用并统一人格、记忆和工具体系。验证任务映射、取消恢复、权限和人格投影。 |
| P7 外部 Agent | 调度 GPT/Codex、Claude 等外部 Agent，使用可替换的 Computer Use Provider，验证批准、会话定位、状态、人工接管、结果与证据。 |
| P8 插件生态 | 在 P3 最小治理之上完善插件生态、兼容矩阵、多 Agent 协同、自动升级回滚、高级沙箱、安全和治理。 |
| P9 工程维护 | 稳定性、容量和性能基线、升级维护、故障恢复、工程优化及回归。 |

设计见[目标架构](WORK_ARCHITECTURE.md)、[事件与 Provider 契约](MESSAGE_EVENT_CONTRACT.md)、[Agent 插件治理](AGENT_PLUGIN_GUIDE.md)和[外部 Agent](EXTERNAL_AGENTS.md)。
