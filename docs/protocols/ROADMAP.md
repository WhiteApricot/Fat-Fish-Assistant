# 工程路线图

P2 已完成 Windows 交付、受控 QQ 聊天、会话管理、安装与迁移及工程收尾。正式基线为 `ac735e0`。本地最终记录列出两套测试的 24 组和 13 组通过证据，并单独记录源码冻结检查差异。本轮 P2 记录没有实机 QQ、云模型或跨主机验收结论。以下各阶段均为计划，P3 是下一阶段。

## 阶段与依赖

**P3 → P4 → P5 → P6 → P7 → P8 → P9** 为主交付顺序。P3 可独立上线，P4 独立运行，P5 联通 P3 与 P4，这三个阶段均无 DSH 依赖。P6 复用 P4 的 Device Service 和 P5 的通信。P7 依赖 P6 的工具接入和权限治理。P8 技术上依赖 P6 的治理和运行时适配，可与 P7 并行开展资料核查、隔离验证设计和兼容测试准备，正式交付仍在 P7 之后。P3 期间可并行设计 P4 的本地接口。外部 Agent 条款核查和 Provider 调研可提前做，真实账号接入遵循 P7 门槛。

## P3 · Linux 迁移与完整聊天系统部署

- **交付**：Linux 兼容矩阵和固定依赖、干净环境安装手册、生产服务定义、迁移与回滚手册、QQ 实机验收记录。迁移 NapCat、AstrBot、模型配置、人格、现用插件与持久化数据。按现有迁移约定冷备、校验和分阶段激活，QQ 登录态由目标重新认证。逐项处理 Windows 路径、脚本、锁、进程调用、凭据保护及第三方二进制。明确服务账号、写入者、服务归属、并发保护、容量和持续运行观察口径。
- **验收**：在实际 Linux 服务器从干净安装和迁移两条路径验证，覆盖 QQ 登录、OneBot 连通与真实模型回复。按现有功能和已启用配置回归私聊、群聊仅 @ 与智能参与、权限允许与拒绝、全局和会话人格、个人及群记忆隔离与检索、提醒、引用和合并转发、已部署的可选语音能力。校验迁移数据、插件和凭据，留存脱敏证据。验证异常退出恢复、日志、启动停止重启、主机重启恢复及备份还原演练。切换与回滚期间同一 QQ 仅一个活动消费者。容量和持续运行结果单列。
- **边界**：未来 Work APP、Device Service 和完整 DSH 环境另行交付。本阶段以 QQ 用户完成实际聊天功能闭环为通过条件。

## P4 · 独立 Work 基础能力

- **交付**：Work Controller、持久任务 ID/状态/记录/结果、基础队列与事件处理、Windows Device Service。覆盖进程、文件操作及传输、桌面和窗口截图、窗口管理、日志和进程监控、任务提醒、结果收集。复核现有管理接口与进程身份机制的复用范围。
- **验收**：DSH 停止或缺席时，可执行脚本和训练、监控进程与日志、查询及传输文件、获取截图，并可查询结果、取消和恢复任务。验证越权拒绝、路径隔离、重复提交幂等、重启核对、断线恢复及退出/取消竞态。

## P5 · Work 与 AstrBot 远端通信

- **交付**：Linux AstrBot 与本地 Windows Work 的认证协议、任务下发和 Task ID 回执、状态/异常/进度通知、结果与文件回传、重连及补发。定义设备寻址和版本协商，为未来远端 Work 预留部署位置。复用管理协议中适用的响应和诊断约定，任务通信单独授权。
- **验收**：QQ 下发确定性任务，收到同一任务的 ID、进度及文件结果。模拟断线、重复与乱序投递、进程重启和凭据吊销，验证恢复、去重、结果授权及唯一 QQ 出口。

## P6 · Work 引入 DSH 与统一治理

- **交付**：Work 的 DSH 适配器、任务分配和结果回传、Device Service 工具接入、Persona Registry、Memory Service、Permission Service、Communication Bridge。固定候选 DSH 版本并记录 Windows SDK、Runtime/Profile、工具和事件兼容矩阵。隔离试接 A 类工具插件。
- **验收**：复杂任务经 DSH 调用受控设备工具并回到 Work，DSH 故障时 P4/P5 基础链路可用。验证人格投影与漂移检测、记忆授权与隔离、工具拒绝和审计、通知经 AstrBot 投递，以及插件启停和越权阻断。

## P7 · DSH 调度外部高能力 Agent

- **交付**：可替换 Computer Use Provider、外部应用接入及条款判定、启动/窗口/项目/提交适配、事件监听与确认、异常和人工接管、结果证据包及工作区隔离策略。
- **验收**：对具备明确授权的 GPT/Codex、Claude 接入路径分别验证，从 QQ 下发到 Work 收回结果、Git Diff 和测试证据。用可控夹具覆盖错窗口、重复提交、审批、输入、额度、错误、取消及误报。禁止自动化或许可未确定的客户端保留人工交接，并单列为未通过自动化接入。考核状态及结果可靠性，长时间执行能力已有用户使用经验。第三方 Provider 可先行验证。

## P8 · Agent 插件生态与安装治理

- **交付**：兼容层、长期维护的安装准则、能力声明和依赖/Profile 兼容记录、隔离/启停/回滚流程、Bili Whale 验证报告。
- **验收**：演练 B/C 类插件准入，验证人格、记忆、调度、授权、通知和回滚。Bili Whale 实测宿主服务、日记域隔离、Webhook 与独立发布授权。无法约束的能力保留在隔离环境，并记录受限原因。

## P9 · 优化与持续维护

- **交付**：Work 调度、DSH 执行与外部协作性能基线，插件兼容回归、治理演进、异常恢复、自动化测试、日志、文档及版本维护流程。
- **验收**：按 P3–P8 基线回归并演练升级回滚、故障恢复与权限撤销。记录队列延迟、任务成功率、重复投递及恢复表现，以实测基线确定持续维护阈值。
