# Fat-Fish-Assistant（肥鱼助手）目标架构

本文描述 P3–P8 的规划。已交付能力见[用户功能](../FEATURES.md)，顺序和验收见[路线图](ROADMAP.md)。

## 核心服务与 Provider

AstrBot 是统一聊天前端，处理适配器生命周期和聊天模型调用。Core 为三个 Provider 类别提供统一身份、权限、人格、记忆和行为记录服务。Provider 经授权的接口访问这些服务，各自维护运行配置和连接健康。

| Provider | 责任与扩展 |
| --- | --- |
| Communication Provider | 提供消息收发、平台账号、会话及能力声明。飞书是主要接入平台，QQ 可同时运行。新平台通过适配器接入，连接、配置和故障隔离。授权绑定把多个平台账号映射为同一身份。引用、转发等能力由适配器声明及降级。 |
| Social Agent Provider | 国内社交内容浏览、理解、自主互动和行为记录。优先 B 站，后续评估抖音和小红书。浏览、评论、私信等分别授权。 |
| Work / Tool Provider | Windows/Linux 设备、文件、任务、训练、Computer Use 与外部 Agent 调度。设备工具和外部 Agent 分别登记能力和资源范围。 |

| 共享服务 | 职责 |
| --- | --- |
| 身份与权限 | 区分机器人、用户、设备和插件主体。按明确授权绑定账号。执行与投递边界重新检查工具、资源、目标、作用域和时效。 |
| 人格 | 保留基础、全局和会话层级。共享身份、价值和行为底线，按接入方生成带版本的投影并核对漂移。 |
| [记忆与行为](MEMORY_SERVICE.md) | 维护完整事件、长期语义记忆与上下文检索。按授权共享跨平台经历，保留来源和状态。 |
| 消息路由 | 按目标身份、平台账号和会话路由，依据能力处理平台差异。投递去重和重试按目标隔离。 |

当前 Windows 兼容链路为 QQ → SnowLuma → OneBot → AstrBot。SnowLuma 仅用于 Windows 临时 QQ 接入。飞书、跨平台治理和 Linux 支持待 P3 交付。现有网关、权限、人格、记忆与提醒模块优先复用。参见[事件契约](MESSAGE_EVENT_CONTRACT.md)和[现行布局](CONTRIBUTING.md#系统设计)。

## Work、设备与远端协作

- Work 先持久化任务、调用者、目标设备、授权范围与幂等键，再回执 Task ID。相同调用者和幂等键只映射到同一任务，参数冲突时拒绝。执行尝试单独编号，重启先对账再决定是否重试。任务取消需底层确认，已完成的外部副作用留审计。
- 设备请求包含任务、调用主体、能力和资源范围。路径以规范化后的实际目标授权，防止路径穿越及链接逃逸。进程绑定启动身份以防 PID 重用，截图绑定具体窗口和所属进程，桌面能力要求正确的交互会话。执行与监控返回结构化事件；Work 按事件 ID 去重并校验状态转换。
- P5 候选为由 Work 发起的认证加密连接。协议形状先定义版本、关联 Task ID、事件 ID、任务内序号与确认游标。发送侧保存未确认事件，重连按游标补发，接收侧幂等处理并可请求状态快照对账。结果和文件使用授权引用、大小及摘要校验，限制接收路径和可见范围。具体传输、凭据轮换和离线缓存期限待 P5 验证。
- P4 先以本机身份和资源策略执行，P5 扩展到设备认证及远程主体映射。P6 将设备与任务纳入 Core 权限模型。任务和设备接口以部署无关的设备标识寻址。

## DSH 接入与证据

P6 评估由 Work 管理的 DSH 子进程与 SDK 适配，映射任务 ID 到尝试及会话 ID。接口语义包括启动、状态/事件、取消、恢复核对和结果回传，具体 SDK 调用以选定版本验证为准。每个任务只暴露所需工具和上下文。限制原生 shell、文件与网络旁路，再做越权测试。DSH 故障仅影响对应复杂任务。

截至 2026-11-05，官方 Python SDK 文档列出 Windows x64、Python 3.10+、配套原生 runtime wheel 以及兼容模型端点与凭据。SDK 启动 `dsh` 并支持 `sdk` 与 `sdk-minimal`，自定义 Profile 需保留 JSON-RPC 服务行。插件通过 Profile 组合及 bundle 层加载，官方提醒本地工具的工作目录并非访问边界。此处为文档核实。P6 仍需固定发布版本并实测启动、事件、取消、重启恢复、受限工具与最小权限。插件管理依赖和 Windows GUI 支持需分别核实。[官方 Python SDK 指南](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/guide/python-sdk.md) · [官方架构](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md)
