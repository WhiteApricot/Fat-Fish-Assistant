# DSH 插件兼容与安装准则

本文用于 P6 工具接入与 P8 Agent 插件治理。现有 AstrBot 原生插件按[独立约定](PLUGIN_CONTRACT.md)维护。

| 分类 | 能力 | 准入 |
| --- | --- | --- |
| A 普通工具 | 按需调用搜索、文件、浏览器等能力，无独立会话与调度 | P6 先验证能力声明、工具权限、输入输出和启停。 |
| B Agent | 可有独立 Agent、会话、人格与记忆 | P8 验证人格投影、领域隔离、共享记忆授权及运行时要求。 |
| C 自主行为 | 定时唤醒、主动发言或操作外部平台，常兼具 B 类特征 | P8 额外验证调度、停止开关、速率限制、通知和逐类发布授权。 |

按实际行为分类，重叠时应用最高治理级别。Fat-Fish Plugin Compatibility Layer 负责发现、登记、兼容检查、配置适配、授权和生命周期。能力声明由兼容层维护，可通过包装适配现有插件。

## 安装与启用

1. **登记**。记录来源、版本或提交、制品摘要、许可、依赖与安装脚本。声明 Profile 所需宿主服务、数据目录、模型、网络目标、凭据、子进程、人格、记忆、调度及主动行为。更新版本和新增能力重新审批。
2. **审查与隔离安装**。先审查源码及传递依赖，再在专用账号、目录及凭据边界中安装。默认关闭调度、外部写入和真实 QQ 通知。限制文件、网络、子进程、资源及运行时权限。无法保证强制隔离的插件只在隔离测试环境评估。
3. **适配**。导入带版本的人格投影，允许领域表达，保持身份、价值、行为底线和用户关系一致。领域数据由插件保管。跨域读写经 Memory Service 授权，记录来源及用途。插件用独立身份向 Bridge 发事件，目标由 Bridge 策略解析。外部评论、私信等分别约束账号、内容、对象、频率及人工审批。
4. **测试**。验证安装和宿主服务齐备、重启及依赖缺失行为、权限拒绝及旁路、人格漂移、领域数据隔离、跨域读写撤销、Webhook 验签与重放、调度窗口与重启去重、发布拒绝和停用后无残留行为。记录版本矩阵、配置摘要和结果。
5. **启用与回滚**。经审查后按能力逐步启用，启用前备份配置和领域数据。禁用时先撤销权限并停止调度、阻断新事件、清理残留进程和定时器，再核查已发出的外部行为。回滚到已验证制品和兼容数据快照，保留审计及失败原因。

## Bili Whale 验证

按 C 类治理。上游 README 说明其自主作息、会话唤醒、日记、Webhook 与 B 站评论及私信能力。其声明需要带 Web 界面的宿主层，依赖 `sessionController`、`webServer`、`connection`，headless 缺服务会等待。README 展示 desktop 安装，列出 Node 18+、专用可写目录及 B 站账号凭据，ffmpeg 用于抽帧。私信专线还有独立账号条件。以上为文档证据。[上游项目与依赖说明](https://github.com/Alterssss/dsh-bili-whale)

P8 固定插件和 DSH 版本，验证实际服务注册、Node 子进程、设置页、调度与重启、独立数据目录和账号前提。SDK Profile 兼容性待验证。优先比较具备所需服务的 desktop/web 组合，必要时独立部署 Extension Runtime。

以测试素材校验人格同步和日记隔离，只将经授权摘要写入共享记忆。Webhook 契约、认证与重放机制待核实，可用受控适配器接入 Bridge，再由 AstrBot 发 QQ。关闭插件直接通知旁路，评论与私信默认关闭，分别验证拒绝、审批及授权撤销；平台条款、账户条件和实际发布能力单列核实。演练一键停用后重启，验证自主唤醒与发送均停止。
