# Memory Service 设计

待 P3-B 实现。当前 Windows 基线沿用 LivingMemory 及现有个人、群组和会话权限。

| 层 | 责任 |
| --- | --- |
| 完整事件记录 | 在授权保留范围内保存原始操作及状态变更。记录事件 ID、操作 ID、尝试 ID、机器人、Provider、平台、平台账号、会话、操作者、对象、发生与接收时间、权限作用域和证据引用。记录计划、执行中、成功和失败，证据不足时保持待核对状态。 |
| 长期语义记忆 | 从授权证据提炼事实、偏好和经历。保留来源、时间、对象、作用域、证据、版本和纠正记录。相关性或衰减影响检索排序，事件保留按数据策略单独管理。 |
| 上下文检索 | 按统一机器人身份、主体、会话和用途计算读取授权，过滤后排序及脱敏。受授权的 QQ、飞书等会话可回忆既有经历并续接任务。群组、个人和私有数据严格隔离，群成员身份不自动授权跨群访问。 |

权限在写入、读取、证据解引用和实际投递时检查。平台身份只通过授权绑定映射，撤销后停止后续访问并清理受影响的缓存。凭据和私密原文按最小必要原则保存，访问审计沿用同一作用域。插件保管自身领域数据，跨域只写获准事件、摘要或引用。

操作以来源命名空间和幂等键关联。同一尝试的重复事件只记录一次，状态乱序须核对，外部副作用不明确时先对账再重试。迁移 LivingMemory 前停写、备份、核对 SQLite/FAISS 和原权限，将旧标识映射到对应作用域。未知归属保留在原隔离范围，验证重复导入、旧包恢复、记录一致性和回滚。参见[数据协议](CONFIG_DATA_SCHEMA.md)和[迁移](../MIGRATION.md)。

研究 SurfCore 的记忆卡、衰减、全量归档、QQ/B 站来源与行为台账。优先验证可复用组件的许可、版本、数据格式及隔离性，再决定适配范围。宿主仍由 FFA 和 AstrBot 按各自职责维护。 [SurfCore 上游说明](https://github.com/Mieksido/surfcore/blob/main/README.en.md)
