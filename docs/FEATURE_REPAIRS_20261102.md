# Dashboard、表情包与长期记忆修复（2026-11-02）

修改限于自有启动、配置脚本与适配插件。沿用锁定的 AstrBot、meme_manager、LivingMemory；未修改第三方核心，未推送 GitHub。

## 实际原因与修改

| 问题 | 原因 | 修改 |
| --- | --- | --- |
| AstrBot Dashboard 自动登录失效 | 启动和登录读取固定的 `dashboard-password.txt`；原生改密只更新密码哈希，旧文件不会同步 | 用户名固定 `astrbot`；捕获 AstrBot 真实生成的初始密码日志，在落日志前脱敏，以 Windows 当前用户 DPAPI 加密、原子保存；旧明文文件成功迁移后删除 |
| 改密后仍使用旧密码 | 无法从 PBKDF2 等哈希可靠恢复新密码 | 原生登录失败时提供一次隐藏输入；先通过 AstrBot 正常认证，再替换加密凭据。错误密码、重定向、远程地址和二次验证未完成时不保存、不绕过认证；重启使用已更新凭据 |
| 仍发送测试表情、缺少自然触发 | 旧实例的默认图包和一次性准备标记未迁移；之前主要依赖回复模型主动输出分类标签，情绪辅助默认关闭，频率提示未启用 | 新实例默认通过现有图包导入器安装鲸鱼娘精选 24 张 GIF；启用现有情绪辅助，复用聊天模型与近四轮上下文；默认 35% 选图机会、每次最多一张，自动表情间隔至少 45 秒及两个回复；明确请求另行处理，纯文字要求优先 |
| 旧测试图混入用户资源 | 原退役逻辑只处理完全未改动的旧图包 | 完整原版图包备份后卸载；混有自定义资源时，只备份并删除路径、哈希均匹配的六张测试图。保留用户新增或改动的图片、其他文件和自选图包 |
| 图片可能退化为路径 | 表情需要经过选图、装饰和 OneBot 图片组件发送，而非拼接图片路径文本 | 配置 Base64 图片发送，保留现有 AstrBot QQ 适配。验证真实 OneBot `image` 段内包含原始 GIF 字节，512×512、8 帧不变；直接采用仓库的 GIF，WebM 属于 Telegram 素材，无需当成插件安装或转码 |
| 长期记忆只在明确要求时写入 | 人格提示把主动写入约束为明确说“记住”；原插件的近重复合并主要在批量反思路径，主动工具直接新增 | 新默认人格和运行时策略允许模型自动识别稳定偏好、关系、习惯、持续项目与长期计划；复用 `memorize_long_term_memory` 和原有数据库、索引、权限与会话/人格隔离；无价值内容不调用工具 |
| 凭据、重复和纠错控制不足 | 明确记忆只过滤单种 `sk-`；主动工具没有覆盖反思的去重路径；改正文后原生召回仍可能优先使用旧摘要 | 为现有工具与引擎写入增加凭据过滤；自动反思过滤低价值摘要；主动写入复用原生作用域检索与合并接口，只有内容或关键事实一致才合并，不凭相似度吞掉相反偏好；串行化检查与写入；纠错同步更新召回摘要、清除过时关键事实；保留 `/记忆更新`，新增当前授权会话的 `/记忆删除` 可逆归档 |

表情资源：[Dejavu Moe / deepseek_wale_girl](https://github.com/DejavuMoe/deepseek_wale_girl)，锁定提交和逐文件 SHA-256 见 `manifests/starter-memes.json`，保留 MIT 许可与来源说明。

## 安装与交付

修复已进入正式源码、默认安装流程和新的源代码提交包。新安装通过原有脚本获取同一锁定版本的插件和鲸鱼娘资源。已有安装请使用安装向导的“修复”流程，在正常停止后更新自有发布代码；版本化的体验配置迁移会保留用户资源、配置副本和权限。

DPAPI 凭据与 Windows 用户/主机绑定；改密后或换用户、换主机时，按设置入口提示隐藏输入当前 Dashboard 密码一次。二次验证仍通过原生 Dashboard 完成。`/memory delete 编号`、`/记忆删除 编号` 仅处理本人私聊；`/群记忆 delete 编号` 仍要求本群管理权限，不能指定其他会话。

提交包不包含本机账号、密钥、聊天记录、测试数据库或运行时目录；未覆盖之前的交付 ZIP。
