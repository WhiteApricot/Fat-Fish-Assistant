# Windows SnowLuma 官方接入

SnowLuma 是 Windows x64 的 QQ 兼容方案。FFA 固定使用 2.4.2 Full 官方 ZIP，单独放置。Full 已包含 Node，桌面 QQ 由腾讯官方渠道提供。 [固定文件名、来源和 SHA256](../manifests/snowluma/windows-x64.json)

如果官方发行页或下载地址暂不可用，可使用手头已保存的官方原版 ZIP 走离线入口。安装器会核对文件大小和 SHA256。首次接入请先取得与清单匹配的官方发布资产。

## 获取程序与打开窗口

使用 `python -B ffa.py --root "<FFA 安装目录>" snowluma <操作>` 运行下表命令。FFA 安装请使用[快速开始](QUICK_START.md)中的双击入口。

| 操作 | 用途 |
| --- | --- |
| `acquire --destination "<独立 SnowLuma 目录>" --archive "<原始官方 ZIP>" --offline` | 使用用户提供的本地原始官方 ZIP，校验后解压并登记 |
| `launch` | 打开已校验目录里的官方 Launcher，WebUI 仅监听本机。重复打开会检查已有窗口和端口 |
| `webui` | 等待官方 WebUI 首页可访问，然后打开浏览器 |
| `guide` | 显示本实例的 OneBot 地址、填写项和操作顺序 |
| `copy url` / `copy token` | 复制地址或令牌到剪贴板，结果和普通日志不显示令牌 |
| `status` / `verify --timeout 60` | 查看当前分层状态，或在用户完成设置后等待有效的 OneBot 与机器人账号证据 |
| `stop-guide` | 显示官方停机步骤。切回官方 Launcher 按 Ctrl+C，根据窗口提示结束，再执行 `status` |

FFA 启动 Launcher 时关闭 SnowLuma 自动加载。QQ 进程选择、注入、登录及设备确认由使用者在官方界面完成。

默认 WebUI 端口为 5099。若端口已占用，可在 `launch` 指定 `--webui-port`，后续查询复用该 Launcher 端口。独立手动启动的既有安装可用同一选项指定端口。只有经过 ZIP 校验并留有安装记录的程序由 FFA 打开 Launcher，现有独立目录可由用户双击官方入口。

## 登录和设置

1. 在官方 Launcher 按提示阅读并确认协议。初次打开官方 WebUI 时，使用官方窗口提示的登录信息。
2. 在腾讯桌面 QQ 窗口用机器人账号扫码和确认设备。在 SnowLuma 官方 WebUI 的实例页面选中该账号并点击加载。
3. 在该账号的 OneBot 设置新增反向 WebSocket 客户端。用 `copy url` 和 `copy token` 依次粘贴到 URL 和 Token 字段。默认 URL 为 `ws://127.0.0.1:6199/ws`，端口以该实例的 `guide` 为准。
4. 角色选 Universal，消息格式选 array，重连间隔填写 5000 毫秒，关闭该客户端的自身消息上报，并关闭当前账号的状态指令。SnowLuma 的状态指令默认开启，关闭后由 AstrBot 统一处理聊天。保存并启用连接后清理剪贴板。
5. 让 AstrBot 保持运行，然后执行 `verify`。读到反向连接、OneBot 服务、QQ 在线和绑定身份四层证据后，按[账号与权限](PERMISSIONS.md)完成主人验证或绑定，再发一条私聊检查实际回复。

WebUI 可打开表明本机管理页有响应。OneBot 在线和身份匹配来自 AstrBot 现有的已鉴权连接。实际消息收发请在已接入的 QQ 客户端验证。

## QQ 聊天与媒体边界

私聊和群聊共用 FFA 的统一身份、权限、人格和记忆。群记忆默认关闭。群聊配置和主人绑定见[账号与权限](PERMISSIONS.md)。

QQ 引用支持有符号消息 ID。FFA 通过当前账号的 OneBot 消息查询验证引用归属，仅使用当前会话的相邻历史。查不到原消息或校验失败时，引用内容不会进入模型上下文。

QQ 图片、文件或合并转发与同一发言者紧接着发来的文字可以合为一次回复。文件处理完成后才进入模型。附件若不能使用 DeepSeek 文件解析，FFA 会尝试在大小限制内按纯文本读取，不执行 HTML 或脚本。

合并转发读取依赖 SnowLuma 返回的节点，嵌套节点缺失时以实际可读内容为准。图片、语音、视频和文件的可读程度受平台和模型限制。主动语音、视频、文件和合并转发发送不在本轮验收范围内。QQ 原生撤回按机器人、会话、作者和消息 ID 核验，随后取消待发回复，排除相关引用、历史和缓存，并清理已记录的统一记忆。旧消息可通过已有入站记录核验。缺少原作者证据时，只拦截相同来源的迟到消息。

未加好友的用户通过 QQ 群发起临时私聊时，FFA 沿同一临时会话发送添加好友及主人联系提示。普通非好友私聊的送达取决于 QQ 是否允许该路由。

## Windows QQ 验收

2026-11-17，操作者在 SnowLuma 2.4.2 与固定版 AstrBot 环境完成 QQ 单平台实机验收，包括群临时私聊的非好友提示、私聊和群聊撤回以及撤回后的记忆和上下文清理。另通过 143 项离线核心与管理测试，以及 30 项固定版 AstrBot 原生测试。

## 常见提示

| 提示 | 处理方式 |
| --- | --- |
| 校验失败 | 核对 ZIP 名称、大小和 SHA256，换用来自官方渠道且匹配的原始资产 |
| Launcher 尚在运行 | 查看旧官方窗口的协议或错误提示。停止后退出窗口，再尝试启动 |
| WebUI 未就绪或端口冲突 | 检查官方启动窗口，等待协议确认完成，必要时改用空闲回环端口 |
| 反向连接未就绪 | 核对 AstrBot 已启动、URL 端口与路径、Token、角色及保存后启用状态 |
| QQ 在线或账号未通过 | 在官方 WebUI 核对加载状态和登录账号，与 FFA 登记的机器人号码一致 |

SnowLuma 的官方配置、QQ 登录态和运行数据继续由其官方渠道管理。 [依赖与许可边界](DEPENDENCIES.md)
