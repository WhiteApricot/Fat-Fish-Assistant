# 工程工作流

## 目录
- `Fat-Fish-Assistant/` 是唯一正式开发工程、Git 根和发布包；自有源码、脚本、模板、测试均在此维护。
- `Fat-Fish-Assistant.local/` 是不入 Git 的工作区：实际运行实例、独立测试实例、缓存、日志、临时构建、迁移包和验证结果均在此保存，不作为源码发布目录。
- 功能、集成和真实服务测试只在 local 的独立实例运行，优先使用 `ux-validation/`；不得覆盖现有正式运行实例。单元测试可引用正式源码，但产物必须写入 local。
- 禁止在正式工程中启动服务、生成数据库、写测试数据或下载外部依赖。
- `Backup/` 只保存历史工程及必要恢复材料，不作为开发、构建或发布基础。

## Git
仅在正式工程根使用现有私有 GitHub 远端。重要阶段完成、稳定功能验收和正式交付时集中提交推送，不作碎片化提交。推送前检查密钥、聊天、数据库、运行数据、私人路径、外部依赖；local、Backup 及工作区其他目录不得提交。不擅自公开仓库，不强制覆盖远端历史。

## 开发
优先插件化、模块化、接口解耦；新功能优先独立插件或适配模块。不修改 AstrBot、NapCat 等外部依赖核心；不可避免的兼容补丁必须走既有 patches，记录上游版本、前后哈希及恢复方法。不将私人配置、身份、数据写入源码，不破坏权限、黑名单、群聊和消息发送边界。不用 Computer Use 或 GUI 自动化代替用户；QQ 扫码、NapCat 登录和外部授权由用户手动完成。不执行未经授权的破坏性操作。

## 验证
优先合成数据和独立测试实例，真实测试不得污染正式实例。失败保留日志和复现步骤；未执行不得标记通过。重要功能必须有自动化回归测试。交付说明区分自动验证、真实服务验证和人工待验收项目。
