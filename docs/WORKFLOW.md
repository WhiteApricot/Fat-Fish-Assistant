# 工程工作流

## 基本原则

所有工作均遵守：**测试在 Local 路径进行，所有修改同步到正式路径交付。**

- 正式路径为 `E:\AI_Chat\Fat-Fish-Assistant`，是唯一源码、安装脚本、配置模板、测试代码和发布包来源。
- Local 路径为 `E:\AI_Chat\Fat-Fish-Assistant.local`，用于独立测试、构建及保存运行数据和验证结果。
- 在 Local 副本或实例中完成的修复，必须同步回正式路径对应的自有代码、配置、适配层和测试；不得只修好本机测试实例。
- 交付前核对正式路径与经过验证的修改一致；需要生成或更新提交包时，以正式路径为来源。真实账号、凭据、聊天和测试产物保留在 Local，不同步进源码或提交包。

## 目录
- `Fat-Fish-Assistant/` 是唯一正式开发工程、Git 根和发布包；自有源码、脚本、模板、测试均在此维护。
- `Fat-Fish-Assistant.local/` 是不入 Git 的工作区：实际运行实例、独立测试实例、缓存、日志、临时构建、迁移包和验证结果均在此保存，不作为源码发布目录。
- 功能、集成和真实服务测试只在 local 的独立实例运行，优先使用 `ux-validation/`；不得覆盖现有正式运行实例。单元测试可引用正式源码，但产物必须写入 local。
- 禁止在正式工程中启动服务、生成数据库、写测试数据或下载外部依赖。
- `Backup/` 只保存历史工程及必要恢复材料，不作为开发、构建或发布基础。

## Git
仅在正式工程根使用现有私有 GitHub 远端。重要阶段完成、稳定功能验收和正式交付时集中提交推送，不作碎片化提交。推送前检查密钥、聊天、数据库、运行数据、私人路径、外部依赖；local、Backup 及工作区其他目录不得提交。不擅自公开仓库，不强制覆盖远端历史。

## 开发
优先插件化、模块化、接口解耦；新功能优先独立插件或适配模块。不修改 AstrBot、NapCat 等外部依赖核心；不可避免的兼容补丁必须走既有 patches，记录上游版本、前后哈希及恢复方法。不将私人配置、身份、数据写入源码，不破坏权限、黑名单、群聊和消息发送边界。不用 Computer Use 或 GUI 自动化代替用户；QQ 扫码、NapCat 登录和外部授权由用户手动完成。不执行未经授权的破坏性操作。

## 三个一键入口联动

未来新增插件或修改功能，只要影响安装、启动或转移，必须同步更新以下三个一键脚本及其共用调用链，保持部署、运行和迁移行为一致：

- `Install-Fat-Fish-Assistant.cmd`：新安装、已有安装修复、插件与资源获取、默认配置及版本迁移。
- `Start-Fat-Fish-Assistant.cmd`：首次与重复启动、依赖服务、旧进程与生命周期恢复、必要的配置迁移。
- `Migrate-Fat-Fish-Assistant.cmd`：迁出、导入及恢复时的插件、资源、配置、用户数据和兼容性检查。

共用实现包括 `scripts/Desktop.ps1` 及其调用的安装、启动、迁移和适配脚本；更新共用逻辑时必须核对三个入口都能获得对应修复。不得只修改插件或 Local 实例而遗漏一键入口。按变更影响在 Local 独立目录验证新安装/修复、启动和转移流程，将验证通过的实现同步到正式路径及提交包；未执行的验证须明确记录。

## 验证
优先合成数据和独立测试实例，真实测试不得污染正式实例。失败保留日志和复现步骤；未执行不得标记通过。重要功能必须有自动化回归测试。交付说明区分自动验证、真实服务验证和人工待验收项目。
