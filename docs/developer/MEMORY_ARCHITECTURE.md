# 当前记忆系统

`GatewayMemory` 从已经准入的事件生成 `Access`，再调用 `MemoryService`。授权私聊以 Principal 为范围，群聊以完整 Conversation Key 为范围。统一记忆启用后，私聊默认开启，群记忆默认关闭。群卡片共享须由群管理员开启，跨作用域使用仍要核对来源。会话历史由 AstrBot 单独管理。

| 数据 | 当前作用 |
| --- | --- |
| Scope 与 Access | 限定读写范围、目的、受众及当前授权。Access 由受信宿主建立并在使用时复核。 |
| Source 与 Activity | 记录平台、实例、Bot、账号、会话以及带事件 ID、时间、类型、状态和证据的活动。Agent 操作记录用 operation ID 关联计划、审批、运行和最终结果。 |
| Fact 与版本 | 按作用域与键保存事实、重要度、修订及证据。修订和删除使用版本检查。 |
| Memory Card | 以活动证据形成叙事卡片，支持合并、编辑、归档和检索。卡片记录可追溯到来源，并受原范围授权约束。 |

## 写入、召回和清理

入站承认后，记忆桥按配置记录入站活动，正文捕获和事实提取可以分别控制。确认发送的回复和主动投递可记录出站活动。受信调用方可用 `record(access, activity)` 写活动，用 `put_fact(...)` 写事实。缺失、过期或跨范围授权会拒绝操作。外部候选活动须有来源和回执，计划不能当成已发生事件。

`search(access, query)` 返回范围内候选事实。`card_records(access, ...)` 读取卡片。`context(access, query, ...)` 生成受预算限制的上下文。召回使用词法检索、记忆清晰度与衰减，配置嵌入服务后可加入向量匹配。后台维护负责部分整理、归档与索引补齐。向量不可用时仍可走词法路径。

删除、重置及核验后的撤回会处理相关事实、活动、卡片投影或索引，并记录擦除信息。授权变化会在后续读写时复核，失去来源权限的共享内容不再用于召回。恢复旧快照需保留已有擦除。把新数据接入记忆前，应明确可撤回边界以及派生索引如何清理。

## 下一阶段需要补齐的边界

当前已有历史活动、衰减、叙事卡片与来源证据，`card.py` 包含 SurfCore 派生机制。当前范围类型为 `private` 和 `group`，尚无独立的 Bot 跨场景经历域，也没有正式的 Principal 社交画像或好感度、熟悉度模型。FFA-N01 从这些数据结构、来源授权和删除链开始评估。
