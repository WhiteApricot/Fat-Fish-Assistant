# FFA-N01 记忆分析与迁移

## 分析任务

MemoryService 用同一事务保存原始 Activity 和待分析任务。聊天请求不会等模型整理。启用 `semantic_analysis`、`auto_extract` 和正文捕获，且宿主具备 AstrBot 模型接口时，符合条件的消息可进入队列。命令、引用、附件、外部材料及敏感内容不进入。关闭语义分析后仍使用原有精简提取和 LivingMemory 反思选项。

维护调度器按批调用当前来源会话配置的 AstrBot `text_chat` 模型。请求禁用工具，使用空模型历史。模型收到授权正文与同范围、同作者的有限自动事实候选。群聊分析不查询私人事实。模型结果通过版本、事件编号、字段白名单、置信度、枚举和敏感信息检查。模型不能指定目标账号或作用域。业务层再次验证来源、授权、擦除状态、当前事实修订和 SQLite 租约。

更新使用既有 Fact Revision，明确冲突保留待处理的事实键及来源。强化只增加当前版本的复习记录。模型可以提出合并同一来源会话内的两张卡片。程序复核卡片和证据，保护置顶、初期及人工命名的卡片，并保留原始来源。撤回使合并卡片失效时，仍有效的原卡片重新可见。后台任务持久化状态，可在进程重启后接管已过期的租约。超时和异常按退避重试，最多八次。来源暂时离线、暂停或无法核验时延后。删除来源会废弃对应任务。默认不回填旧消息。配置卡片容量时，维护记录 80%、90% 和 100% 的占用级别，按现有保护规则压缩。容量级别由本地维护状态提供。

## 画像与经历

画像以 Principal 为索引。当前收集的范围为幽默、玩笑接受度、正式程度、直接程度、详细程度和亲和程度，以及从互动证据累计的熟悉度。画像行仅保存固定字段与数值，文本始终留在原 Activity。通常需要三个跨至少两天的信号才调整一个维度。置信度足够的纠正可立即更新偏好。召回时复核产生该信号的原账号、Provider 和记忆开关。群聊使用同一画像时，玩笑接受度仅作为当前发言者明确主动开友好玩笑时的参考。普通提问、严肃讨论或不确定时保持正常语气。群内实际表达由聊天模型结合当前发言、显式偏好和群聊氛围决定。群记忆关闭时，已准入的群聊仍可使用当前发言者的互动画像和经验证的公开 Bot 经历。此路径不会写入群聊记忆或召回群聊记录。

Bot 经历以配置中的稳定 `agent_memory_id` 标识。经平台确认的主动提交记录按来源范围保存，`AgentRegistry` 也可接收配置后的来源受限经历。来源受限经历按原始授权使用。公开经历须由受信宿主验证阅读或浏览回执，不能由模型或普通聊天自动认定。原生来源和授权主体单独记录。已计划、运行中和失败的操作仍保留在既有账本，不能写成已完成经历。受信生产者可在原账本记录已有可靠证据的取消状态。

公开经历可触发同一队列提炼兴趣或内部目标。相关主题按名称聚合经授权的证据。重复出现可提高权重，拒绝信号和时间衰减可降低权重，超过 30 天的证据不参与当前召回。经历条目保留状态、原平台、时间、活动编号和召回原因。主题字段没有执行权限。经历、主题和画像通过同一 GatewayMemory 上下文入口与现有卡片拼装，在预算内作为资料传入模型。卡片召回先筛选授权证据，再合并词法、向量、重要度、新近程度、复习次数、清晰度与证据类型评分。结果标出词法命中、语义命中或锚点等入选依据。损坏或维度错误的向量会跳过，并在后续维护中重建。配置 Token 预算后使用 AstrBot 的估算器，无 AstrBot 环境按 UTF-8 字节保守裁剪。

## SQLite 升级与回滚

从版本 14 升至 15，在现有数据库中增加语义任务、画像信号、经历、主题、冲突、容量记录和失效计数表。迁移事务保留旧 Activity、Fact、修订、卡片、索引和所有擦除账本。迁移不会创建历史画像或公开经历。版本 15 的 SQLite 库应由对应版本的 MemoryService 打开。

迁移前让实例停止写入，生成经过验证的完整实例备份。先将备份恢复到隔离测试路径，通过 `PRAGMA integrity_check`、`PRAGMA foreign_key_check`、记录数量和代表性授权读取核对，然后在隔离副本上验证最新擦除账本重放。回滚旧程序时恢复迁移前备份，并从较新实例提取最新擦除账本后，在激活前重放。较新版本运行期间的写入需要单独桥接，避免直接降级文件。已撤回或重置的来源使相关画像、经历、主题和任务一起失效。授权变更会继续通过现有 Access 检查阻止召回。
