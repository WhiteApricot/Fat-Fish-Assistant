# FFA-N01 记忆分析与迁移

## 分析任务

MemoryService 用同一事务保存原始 Activity 和待分析任务。聊天请求不会等模型整理。启用 `semantic_analysis`、`auto_extract` 和正文捕获，且宿主具备 AstrBot 模型接口时，符合条件的消息可进入队列。命令、引用、附件、外部材料及敏感内容不进入。关闭语义分析后仍使用原有精简提取和 LivingMemory 反思选项。

普通聊天的分析任务由已提交的回复回执放行。未回复的任务不外发，24 小时后停止等待，原 Activity 保留。纯问候不进入队列。后台每分钟轮询一次。同一个原生账号、机器人、会话和 Principal 累积四个已回复来源，或最近一次回复后空闲 120 秒，就调度分析。每批最多六个来源，公开 Bot 回执单独处理。多条来源共享一次 `text_chat` 请求，结构化提议必须带可在对应来源中逐字查到的短引文。引文复核能约束证据归属，语义判断仍由模型负责。失败的批次经过退避后拆为单条重试。

在授权私聊用 `/memory analyze` 请求下一次轮询处理当前来源的已回复任务，`/memory analysis-status` 查看状态。群管理员可用 `/groupmemory analyze` 和 `/groupmemory analysis-status` 管理本人在本群的队列。手动操作跳过空闲阈值，仍服从原生权限、回复要求和退避。运行状态按 UTC 日累计模型请求数、分析的来源数及输入输出 Token。优先用模型响应提供的用量，否则用 AstrBot 估算。用量不存原文，保留 90 天，无法从中直接得到账单金额。

维护调度器使用当前来源会话配置的 AstrBot `text_chat` 模型。请求禁用工具，使用空模型历史。模型收到授权正文与同范围、同作者的有限自动事实候选。群聊分析不查询私人事实。模型结果通过版本、事件编号、字段白名单、置信度、枚举和敏感信息检查。模型不能指定目标账号或作用域。业务层再次验证来源、授权、擦除状态、当前事实修订和 SQLite 租约。

更新使用既有 Fact Revision，明确冲突保留待处理的事实键及来源。强化只增加当前版本的复习记录。模型可以提出合并同一来源会话内的两张卡片。程序复核卡片和证据，保护置顶、初期及人工命名的卡片，并保留原始来源。撤回使合并卡片失效时，仍有效的原卡片重新可见。后台任务持久化状态，可在进程重启后接管已过期的租约。超时和异常按退避重试，最多八次。来源暂时离线、暂停或无法核验时延后。删除来源会废弃对应任务。默认不回填旧消息。配置卡片容量时，维护记录 80%、90% 和 100% 的占用级别，按现有保护规则压缩。容量级别由本地维护状态提供。

## 画像与经历

画像以 Principal 为索引。当前收集的范围为幽默、玩笑接受度、正式程度、直接程度、详细程度和亲和程度，以及从互动证据累计的熟悉度。画像行仅保存固定字段与数值，文本始终留在原 Activity。通常需要三个跨至少两天的信号才调整一个维度。置信度足够的纠正可立即更新偏好。召回时复核产生该信号的原账号、Provider 和记忆开关。群聊使用同一画像时，玩笑接受度仅作为当前发言者明确主动开友好玩笑时的参考。普通提问、严肃讨论或不确定时保持正常语气。群内实际表达由聊天模型结合当前发言、显式偏好和群聊氛围决定。群记忆关闭时，已准入的群聊仍可使用当前发言者的互动画像和经验证的公开 Bot 经历。此路径不会写入群聊记忆或召回群聊记录。

Bot 经历以配置中的稳定 `agent_memory_id` 标识。经平台确认的主动提交记录按来源范围保存，`AgentRegistry` 也可接收配置后的来源受限经历。来源受限经历按原始授权使用。公开经历须由受信宿主验证阅读或浏览回执，不能由模型或普通聊天自动认定。原生来源和授权主体单独记录。已计划、运行中和失败的操作仍保留在既有账本，不能写成已完成经历。受信生产者可在原账本记录已有可靠证据的取消状态。

公开经历可触发同一队列提炼兴趣或内部目标。相关主题按名称聚合经授权的证据。重复出现可提高权重，拒绝信号和时间衰减可降低权重，超过 30 天的证据不参与当前召回。经历条目保留状态、原平台、时间、活动编号和召回原因。主题字段没有执行权限。经历、主题和画像通过同一 GatewayMemory 上下文入口与现有卡片拼装，在预算内作为资料传入模型。卡片召回先筛选授权证据，再合并词法、向量、重要度、新近程度、复习次数、清晰度与证据类型评分。结果标出词法命中、语义命中或锚点等入选依据。损坏或维度错误的向量会跳过，并在后续维护中重建。配置 Token 预算后使用 AstrBot 的估算器，无 AstrBot 环境按 UTF-8 字节保守裁剪。

群内用语只在群记忆启用时收集。至少两名已授权成员在两个 UTC 日期提供相同释义后，同一群遇到原词时才可提示含义。出现释义冲突时暂停注入。回收授权、撤回或超过 60 天都会减少可用证据。词义不会与另一个群或私聊共享。模型也可建议证据中同时出现的别名与原词，仍需两个成员、两个 UTC 日期，目标释义本身也必须有效。有指向冲突、原词冲突、撤回或过期时停止使用别名。

## Bot 经历语义召回

仅已写入经历投影、仍有证据和授权的记录参与索引。投影来自宿主验证的 Bot 回执，通用出站元数据与用户事实不进入这一索引。SQLite 用 Agent、回执和模型空间唯一标识向量，模型空间包含端点、模型、修订与维度。后台逐页增量扫描，缺失或损坏向量重新写入。原文、证据修改、撤回、重置以及删除账本重放都会清除关联索引。权限暂停先过滤不可读条目，恢复权限后可继续用仍有效的索引。

当前会话先按私聊 Principal 或完整群范围选择候选，并核验原始授权来源。公开经历可在有权的其他会话使用。使用 BM25、余弦相似度、新近程度和完成状态混合排序，检索不再截断到最近 64 条。同文去重，最多返回三条，再核一次来源权限。没有可用向量时使用词法排序。索引随模型空间重新生成。没有为合法的历史回执设置硬性到期日，已失效证据不能召回。

## 延迟预算和故障排查

自动捕获的 SQLite 等待预算为 140 毫秒。Gateway 最多等待捕获 650 毫秒，之后继续回复。锁竞争时用最多 64 条的进程内队列重试三次。重试保留身份和来源检查，原生回复已经记账时，延后写入的输入可以关联到同一回复。队列满、耗尽或进程异常退出仍可能丢失自动采样，监测项会记录正在排队及可观察的丢弃。显式记忆操作保留独立响应和错误。

查询向量最多等 400 毫秒，整个记忆增强最多等 900 毫秒。本地 Embedding 可在回复前访问回环模型，批量索引与聊天并行，同一时刻最多一个底层 Embedding 请求。慢请求可触发本轮词法降级，底层线程释放前仍持有并发槽。云端 Reasoner 仍须有回复回执才可分析聊天。

本机运行 `python fat_fish_management/manage.py memory-status --instance INSTANCE_DIR` 可查看模型空间条目数、维护结果、累计 Embedding 调用与超时、语义经历命中、记忆队列及每 UTC 日的分析 Token。维护状态中 Embedding 成功代表端点返回有效向量，模型空间计数代表已写入索引，语义命中需要实际查询触发。三者独立核对。主人私聊的 `/memory analysis-status` 同时显示最近七个有记录 UTC 日的分析用量。

## 独立的公开经历

授权读工具可以提供公开资源 ID，宿主的独立核验器必须以该 ID 和原生回执验证公开性，并返回受控的标题、摘要、主题和权重。群授权、插件读授权和公开性分别检查。缺少核验器或核验失败只保留原来源允许的 Activity，旧发布接口不会自动迁移到新的全局信任级别。

版本 18 在原 SQLite 中按 Agent 与公开内容 ID 去重。公开摘要和证据摘要值独立保存。跨平台的授权会话可使用公开投影，模型看不到关联用户、会话 ID、私聊评论或内部回执。私聊重置擦除私人关联，仍公开的独立内容可以保留。主人私聊可使用 `/memory forget-public <公开内容 ID>` 清除公开快照和派生索引。该操作记录擦除账本并在恢复时重放。宿主确认资源从公开变为无效后，也应调用同一失效路径。当前没有主动重新验证外部地址的后台爬虫。

每次召回先取最多 96 条置顶或近期投影，另有最多 24 条高重要度投影。最多 12 个倒排词各取 12 条，最多 264 条公开候选进入混合排序。向量维护每周期最多更新四条活跃公开投影。超过 180 天且低重要度和未置顶的向量分批移出，存量内容仍可词法发现。主人可用 `/memory pin-public <公开内容 ID>` 保留重要内容。没有自动删除公开原始证据。

具有三个不同公开对象、两个 UTC 日期且加权证据充足的主题可进入持续兴趣摘要，并提供公开证据 ID 和修订。主题按时间衰减，删除证据后重新生成。公开阅读只能证明接触或获得资料，不能自动证明掌握、同意或形成私人目标。该摘要不修改 Persona。主人可用 `/memory focus confirm|activate|complete|abandon <主题>` 更新已有持续关注的反馈状态。状态切换有顺序限制，保存证据摘要及修订。完成反馈只代表内部关注已结束。目标语义合并、自动生成行动计划和主动行为调度仍未实现。

## SQLite 升级与回滚

当前 SQLite 版本为 18。新增公开经历投影、词项、模型空间向量、公开关注反馈和群别名证据。版本 17 将无回复且持有旧租约的任务恢复为待回复，并增加可重建的 Bot 经历向量表。版本 15 增加语义任务、画像、经历、主题和容量等表。版本 16 增加回复放行、用量统计和群内用语证据。升级时只有可从现存日志关联原生回复回执的旧对话任务能继续进入队列。迁移事务保留旧 Activity、Fact、修订、卡片、索引和所有擦除账本。迁移不会创建历史画像或公开经历。版本 18 的 SQLite 库应由对应版本的 MemoryService 打开。

迁移前让实例停止写入，生成经过验证的完整实例备份。先将备份恢复到隔离测试路径，通过 `PRAGMA integrity_check`、`PRAGMA foreign_key_check`、记录数量和代表性授权读取核对，然后在隔离副本上验证最新擦除账本重放。回滚旧程序时恢复迁移前备份，并从较新实例提取最新擦除账本后，在激活前重放。较新版本运行期间的写入需要单独桥接，避免直接降级文件。已撤回或重置的来源使相关画像、经历、主题和任务一起失效。授权变更会继续通过现有 Access 检查阻止召回。
