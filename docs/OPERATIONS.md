# 运维、生命周期与恢复

> 本文覆盖当前 Windows 基线的 FFA 管理核心。SnowLuma 的启停、扫码与配置均通过官方入口进行。

普通安装、启动和迁移使用根目录三个 CMD，操作见 [快速开始](QUICK_START.md)。本文件保留维护者所需细节，不要求普通用户学习管理命令。

## 安装、检查、修复

安装根包含 cache、envs、releases、instance、logs 和受管理状态。未知非空目录拒绝接管；固定下载先写唯一 partial，再验证 SHA256。虚拟环境在最终版本路径创建，固定 sdist 通过固定构建工具产生本地 wheel，逐项版本核验和 pip check 通过后登记。中断构建只对带匹配项目标记的目录归档重试，不删除未知数据。

重复检查不覆盖身份、Key、配置或聊天。安装向导的修复选项先正常停止服务，再复用已有依赖。`install --repair` 仅接受相同依赖、固定上游版本和已允许的兼容补丁变更；自有代码变化复用既有事务升级。初始化在目录激活后、登记前中断时，只有根与实例的匹配事务归属证明、身份和完整性检查通过才恢复登记。

安装根、实例、快照及解密暂存目录用 Windows DACL 限制为当前操作者、SYSTEM、Administrators；DACL 不等于加密。缺少 Microsoft 运行库且用户明确接受许可时，才获取固定哈希的官方安装程序并请求必要系统确认。进程级脚本策略不会改写全局执行策略或系统 Python。

## 日常启动与停止

新安装为本机模型选择空闲端口，不会凭端口接管另一份安装的服务。附加功能失败时，可双击安装入口选择修复；先受控停止，再保留密钥并重新选择可用端口。维护接口为 config initialize-local-models。分条与原创表情仅在首次体验配置时准备，重复执行不覆盖用户后续修改。SnowLuma 的 WebUI 地址及初始登录步骤以官方 Launcher 提示为准。

QQ 掉线时从 SnowLuma 官方 WebUI 查看登录状态，按提示扫码或完成设备确认。OneBot 令牌与两套管理页密码各自独立。

CMD 使用 `daily-start`，仍调用既有组件管理和健康接口：依次处理 Embedding、Speech、AstrBot，Core 随 AstrBot 加载；已运行服务复用，未安装组件跳过，可选组件失败单独报告。记忆数据需要恢复但 Embedding 不可用时，Chat 不会绕过一致性保护。stop 按反序停止 FFA 受管服务，先触发 Chat 原生退出和索引落盘。全局启停返回 SnowLuma 官方人工步骤，结果的 complete 字段标记待完成。

启动管理流程持有独立 `.start-lock`；恢复阶段取得 `.instance-lock`。子进程先取得生命周期锁，再写 RUNNING。就绪检查核验实例进程身份、端口与本次启动器的进程链，支持 Windows venv 启动器 PID 与实际 Python PID 不同的情况。冷启动最长等待约 10 分钟并显示进度；超时保留日志，不能把端口监听视为完整 QQ 验收。

独立只读健康适配插件通过已有 OneBot 连接调用 get_status/get_login_info，不注册消息处理器、不发送消息、不开放新端口。私密健康证据核验 PID、实例身份和时效。分别报告反向通道、OneBot 服务、QQ 在线、账号匹配及 Core 插件加载。模型调用和业务聊天需另行验证。旧发布若缺少适配器，应通过受控修复更新；不能把缺少协议证据误报为 QQ 连接成功。

## 异常退出

- RUNNING 指向已不存在 PID：先取得 OS 锁、验证 SQLite 和原生向量一致性，通过后归档标记及时间/原因，再启动。
- PID 存在但不属于本实例、PID 复用或 OS 锁占用：拒绝控制，不终止其他进程。
- DIRTY：不能直接清除。先检查一致性；主记忆索引可通过既有 MemoryEngine/IndexValidator 修复，原 DB/索引及故障标记保留副本，失败保留 DIRTY。缺少 Embedding、损坏 SQLite、graph_memory 或未知向量状态时拒绝自动恢复。
- upgrade-journal.json：日常入口先调用原 recover-upgrade，不与失效生命周期标记混用。活动或状态模糊时停止恢复，保留证据。

优先使用安装向导的修复入口。诊断在安装根 logs、instance/logs、private/data-integrity.log 及 private 下的生命周期/索引修复历史；不得直接公开这些私人材料。

## 迁移与切换

完整操作和包含/排除清单见 [MIGRATION_CHECKLIST](MIGRATION.md)。CMD 完成受控停止、冷快照、标准认证加密、自动依赖准备、staging 校验和新目录激活。目录形式 backup/restore API 继续保留，不能把未加密目录快照当作加密迁移包。

迁出源保持暂停；需要撤销时必须先停用目标，再在源安装向导中明确确认，底层为 `resume-source --confirm-target-offline`。跨机器互斥不能替代设备使用者确认：不要绕过源暂停记录或在其他程序中双开同一个 QQ。SnowLuma 在目标通过官方流程接入，登录与设备认证由用户完成。

## 升级与回滚

固定来源组装并校验新 release，停止写入后事务切换插件和发布指针；故障由原 journal 回退/恢复。插件自定义资源及已识别的私密图床配置在升级和恢复时保留；锁定程序漂移或资源与程序冲突拒绝覆盖。数据库不回灌、不做未经测试的 schema 降级，新聊天不能用旧快照覆盖。

既有 patches 记录上游版本、前后 SHA 和恢复方式；AstrBot 通过固定补丁部署，SnowLuma 运行文件由官方发行包提供。回滚采用重建并切回已校验发布，不在运行目录逐文件反向编辑。

## 常见失败

- 密码错误、包损坏或标签验证失败：确认密码及包 SHA，原目标不覆盖。
- 缓存/程序 SHA 不符：保留隔离材料，不修改 manifest 来放行。
- 非空未知目标或已有实例：换新空目录；禁止伪造管理标记。
- 协议未连接：检查向导中的机器人 QQ、独立运行包完整性和手动登录；飞书排查见 [飞书接入](LARK.md) 和 [故障排查](TROUBLESHOOTING.md)。
- SQLite/向量状态不支持：保留原件，按诊断使用测试过的恢复适配器；不能删除 DIRTY 强行启动。

代码更新后通过原安装向导的修复入口重建并切换发布。当前源码对比覆盖核心及自有插件。
