# 故障排查

| 现象 | 检查 |
| --- | --- |
| 安装报下载或校验失败 | 检查下载连接、许可和安装日志，重新运行安装向导复用已校验缓存。 |
| 已打开管理页但 QQ 无回复 | 先看 `health` 的 OneBot、QQ 在线和 Core 字段，再核对模型及群权限。反向通道未建立时，在官方 SnowLuma WebUI 核对回环地址、令牌和机器人账号。 |
| 飞书有连接但收不到消息 | 核对已发布版本的应用订阅、收件权限、应用可用范围和机器人身份。已开权限后仍需添加 `im.message.receive_v1` 应用订阅。参见 [飞书接入](LARK.md)。 |
| 引用只能看到原文 | 邻近历史依赖相应会话的读取权限及可读记录。 |
| 重复启动或端口占用 | 查看管理页及启动日志。受管理实例会按身份复用；未知进程应由其所属应用处理。 |
| DIRTY 或索引校验失败 | 先保留诊断材料，按[运维指南](OPERATIONS.md)检查 Embedding 和数据一致性。 |
| 需要联网但没有结果 | 用 `/webresearch` 检查当前会话状态，并核对 DeepSeek 凭据和服务可达性。请求实时资料时可以明确说要联网核对。 |
| 自然语言管理无反应 | 由主人或全局管理员检查 `/naturalcommand global`，再核对当前会话开关。群聊按群模式触发。 |
| 恢复包被拒绝 | 核对密码、包哈希、软件兼容及新空目录条件。 |

安装根 logs 和 instance/logs 用于本地诊断，分享前先清理账号、令牌、聊天及绝对路径。

若桌面入口报告活动发布与源码不同，从安装向导执行修复，待发布切换后重试。旧发布仍可通过既有回滚操作恢复。
