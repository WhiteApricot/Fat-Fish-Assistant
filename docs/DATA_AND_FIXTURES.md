# 数据、身份与合成测试边界

新安装创建空白实例、独立部署标识、随机本地凭据和用户指定的 QQ 主人身份。没有默认群白名单、导入聊天、真实记忆或复制旧 QQ 登录。`fat_fish_guard` 为唯一注册的自有入口；`feiyu_guard` 仅为导入兼容层。

实例 schema 1、管理契约 1、快照 envelope 2、原生 LivingMemory db_version 8 分别校验，不能混称一个全局数据库版本。权限文件与不可变实例主人必须一致，未知版本或补丁前置哈希不一致时拒绝操作。品牌更名不改写 QQ 身份、权限映射、记忆作用域或向量 ID。

默认回归中的身份 `100/200/900`、聊天、权限、HTTP 服务及进程均为合成夹具。升级测试只对空白合成实例切换代码和插件，不恢复个人数据。管理接口的 restore 测试仅验证分派契约，底层恢复调用被模拟，不能记作迁移验收。

未来完整合成迁移保留在 `tests/test_migration.py`，须在授权的 VM 验收时显式选择。默认 `tests/run_all.py` 不执行它；本轮未进行新的备份恢复或跨目录数据迁移。

备份必须先停止消息写入和索引后台任务。SQLite 使用 backup API 并校验，跳过 WAL/SHM；FAISS 遵循原生 LivingMemory 保存/重建及损坏处理机制。多个数据库不宣称未经验证的原子一致性。冷备份包含凭据，私有目录权限不等于加密；跨机传输需使用用户控制的加密介质。

测试步骤与待填结果见 [VM 安装表](VM_INSTALL_CHECKLIST.md) 和 [跨主机迁移表](MIGRATION_CHECKLIST.md)。真实 QQ 登录、第二群授权边界、完整私聊合并矩阵及模型语义效果需要人工证据，不能由合成服务替代。
