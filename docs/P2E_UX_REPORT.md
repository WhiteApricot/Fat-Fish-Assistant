# P2E-UX 实现与验收记录（2026-10-31）

本轮只优化 P2E，不进入 P2F/P3。最终25组回归全部通过，执行期间源码冻结；用户已确认修复后的扫码、分条回复和基础表情发图通过。本报告区分自动回归、真实本机服务、合成协议对端与人工操作；干净 Windows 和真正跨主机仍待验收，不用同机迁移替代。

## 1. 工作流

新增约一页 [WORKFLOW.md](WORKFLOW.md)，集中规定正式源码/Git 根、local 独立实例、Backup、隐私检查、集中提交、插件化、既有补丁机制和测试证据要求。README、CONTRIBUTING 及相关文档引用该规范。自动测试均使用仓库外 local/ux-validation；人工安装沿用用户选择的 LocalAppData 安装位置。没有操作 closure 正式实例。

发现既有及本轮产生的控制脚本字节缓存后，已可逆归档到 local，并将 Chat 与其子进程缓存固定至实例 data/temp/python-cache。最终实际 CMD 复测后，正式目录无新增字节缓存、数据库、依赖或运行数据。此为收口清理和修复的结果，不冒称全程没有产生过缓存。

## 2. 双击安装

入口为 **Install-Fat-Fish-Assistant.cmd**。向导确认默认用户目录或文件夹选择器、第三方许可、组件、主人身份及隐藏的 DeepSeek Key；复用原安装器、固定版本/SHA256 和独立 Python 环境。仅缺失运行库时调用固定官方安装程序，必要系统确认由用户完成，不修改系统 Python 或全局执行策略。失败保留阶段、归属证明和日志；重复执行复用已验证环境，未知非空目录不接管。显式修复走既有事务升级，不切换未经验证的依赖版本。

用户已确认本机安装、扫码、OneBot 和授权消息通过；随后提出提示过于工程化、登录页自动填写、分条及表情不可用等体验缺陷。本轮保留并修复配置子命令误绑定、新命令漏登记、QQ 页面根跳转丢失参数、缺少 /webui/ 页面前缀以及模型端口与另一安装冲突的问题。每项修复均有独立证据，修复后真实页面仍单独验收。网络/低磁盘/缺运行库有故障模拟；未做干净 Windows VM 全流程。

默认窗口改用普通中文进度，不显示管理 JSON。首次配置启用原生换行分条（代码块保持完整），通过上游包导入器安装六张自有绘图代码生成的小鱼表情，每次回复最多一张。重复准备保留用户修改，配置副本留在 private/config-history，权限文件不变。新实例自动避让被其他安装占用的模型端口，复用既有配置器且保留密钥；当前用户的 Embedding 已在独立端口通过实际鉴权、错误密钥拒绝及512维检查。

本机 QQ.exe 注入报缺少 loadNapCat.js 后，取消 QQ.exe 选择，改用 **NapCat 官方 v4.18.41 Windows Node 包**，配套 QQ 9.9.31-49738、Node 22.11.0。发布包 SHA256：
`51fbb10e7bcd56b0c2a6de86c37811e7518330e48a137ac689ab1e4d8627d3f0`。
另有 napcat-node-lock.json 原生文件校验。旧安装通过 prepare-napcat 保留配置及旧程序目录后切换，不复制 QQ 登录态，不修改系统 QQ 程序。上游单进程模式确保无重启监督进程遗留。

**限制**：独立的是程序载荷和 NapCat 配置。QQ 原生个人文件夹仍由腾讯组件解析，探测发现可能沿用本机腾讯配置，不能宣称原生缓存也完全隔离。首次切换清空自动登录账号，启动不传快速登录参数，并屏蔽继承的快速登录密码环境变量。用户必须选未被其他实例使用的机器人账号手动扫码；未修改全局个人文件夹配置或伪造设备认证。

## 3. 日常启动

入口为 **Start-Fat-Fish-Assistant.cmd**。读取安装登记，通过原 JSON daily-start 顺序启动/复用 NapCat、Embedding、Speech、Chat；可选失败单独警告，仍尝试核心 Chat。检查环境完成凭据、管理页身份、模型鉴权、QQ 登录及 OneBot 在线身份。独立健康插件只查询既有连接的状态/登录身份，不发送消息，不放宽授权。自动打开本机页面，扫码由用户完成；失败保留窗口和日志位置。

实际 CMD、Unicode stdin、JSON/stderr、真实 Chat/模型启停已有证据。l 轮实际 CMD 启动及正常停止通过，m 轮新增登录恢复前端分支通过；此前 g/h 轮暴露的进程提前退出、启动时 CIM 字段暂缺已修复，不再写入不完整凭据。没有界面点击或 Computer Use，无界面 CMD 调用不能冒充人工双击。

QQ 页面使用固定版本实际前缀 /webui/web_login，并在内存中加入本机 token；HTTP200、无跳转丢参以及端口归属均已在当前用户安装验证。根路径会301且丢查询参数，单独 /web_login 会404，均有失败证据，不能把先前仅检查拼接 URL 的测试当作真实页面通过。日常启动不再额外打开易混淆的肥鱼设置页；设置页密码与 QQ token 不混用。

原生 QQ 曾卡在 reconnecting，网页刷新无法生成二维码。新增只读 login-status 与受控 recover-login，连续确认卡住且没有登录/扫码确认进行中时，复用原生命周期重启本安装的 Node 进程。每次启动向导最多实际重启一次，再打开带凭据的正确页面；不重启已登录、扫码中、自行恢复或外部只读服务。实际故障恢复后为 waiting_qrcode、qr_available=true，用户完成手动扫码及消息/图片验证。前端等待采用真实时间截止，不以循环次数虚称时限。

## 5. 迁出与迁入

双击 **Migrate-Fat-Fish-Assistant.cmd**，选择 1 迁出：确认受控停止、选保存位置、设置并确认隐藏密码。程序停止全部受管理写入者，核验锁、生命周期及升级状态、SQLite/原生向量一致性，创建快照，输出一个 .ffa.zip、大小、文件数、SHA256。源实例保持暂停。

目标选择 2：选包、输密码、选新空位置、确认源停止并接受外部许可。程序认证包及软件/数据兼容性，自动准备固定环境，先恢复 staging，重建插件代码并恢复资源、密钥和身份，调整受支持机器路径/端口、设置文件权限，通过原生校验后原子激活、登记安装。已有目标或新聊天拒绝覆盖；失败保留证据。目标 QQ 手动重新登录，健康不等于消息验收。

撤销源暂停前必须先停目标，再明确确认 resume-source。工程内互斥不能代替用户对另一台主机及其他 QQ 软件的确认。

## 6. 加密和完整性

使用现有 cryptography 的 **AES-256-GCM** 流式认证加密；随机 salt16/nonce12，scrypt N32768,r8,p1 派生密钥，头部 AAD，标签16字节。外层 ZIP 只有密文条目，文件名/清单/配置都在密文中。密码只经隐藏输入/stdin，不保存；明文临时目录限当前用户访问，退出清理。遗失密码无法恢复。

先完成认证再解析/释放内部 ZIP；拒绝穿越、盘符/ADS、符号链接、保留名、大小写重复、文件目录碰撞及异常展开量（64GiB/10万文件上限）。另有逐文件 SHA 与 AESGCM 互操作测试。错误密码、篡改、版本/清单不符、已有目标均有安全失败证据。

## 7. 异常退出恢复

先取得启动互斥，核验 RUNNING 的 PID、创建身份/命令/实例归属、生命周期 OS 锁及其他写入者。子进程拿到生命周期锁并写 RUNNING 后才交接成功；支持 Windows venv 重定向的实际子 PID。并发最多一个 Chat 生命周期。

失效 RUNNING：SQLite/原生向量一致性通过后归档并继续。DIRTY 不直接删除；原生 IndexValidator 验证，必要时调用原 repair_index，先保留原 DB/索引/标记。坏 SQLite、缺 Embedding、graph_memory、未知索引及无法证明一致状态保持拒绝。有效/复用 PID 和锁占用不杀进程；upgrade-journal 走 recover-upgrade。归档含检测/恢复时间、原标记时间和原因，不伪造未知的准确故障时间。

实际故障已覆盖正常启停/重启、突然终止、遗留 RUNNING、健康 DIRTY、坏 SQLite、坏 FAISS 重建及原件保留、Embedding 缺失/恢复、graph_memory、锁占用、PID 复用、并发双启动；原升级测试覆盖中断/回滚。用户原报 running=false/dirty=false/clean_stop=false 已在真实独立 Chat 实例安全恢复。
